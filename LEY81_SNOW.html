Modulo 1 Fundamentos de la Ley 81 y Arquitectura Snowflake Arts. 1-5, 20

Que es la Ley 81?

La Ley 81 de 26 de marzo de 2019 es la legislacion panamena que regula la proteccion de datos personales. Establece los derechos de los titulares, las obligaciones de los responsables y encargados del tratamiento, y las sanciones administrativas aplicadas por la ANTAI (Autoridad Nacional de Transparencia y Acceso a la Informacion).

Conceptos fundamentales (Arts. 1-5)

Dato PersonalInformacion relativa a una persona natural identificada o identificableColumnas clasificadas como NAME, EMAIL, PHONE_NUMBER, etc.
Dato Personal SensibleOrigen racial/etnico, salud, vida sexual, biometria, genetica, opinion politica, conviccion religiosa, filiacion sindical, antecedentes penalesColumnas clasificadas como ETHNICITY, MEDICAL_DATA, GENDER

Encargado del TratamientoPersona que realiza el tratamiento por cuenta del responsableRoles/usuarios con acceso a los datos
Oficial de Proteccion de DatosPersona designada para supervisar el cumplimiento (Art. 17, num. 7)Role LEY81_OFICIAL_DATOS en Snowflake
TratamientoCualquier operacion realizada con datos personales (recoleccion, almacenamiento, consulta, etc.)Queries, ETL, transformaciones en Snowflake

Bases Legales para el Tratamiento (Arts. 8-9)

La Ley 81 establece bases legales para el tratamiento de datos personales. Cada tabla con datos personales debe tener su base legal documentada:

#Base LegalTag Value
1Consentimiento libre, previo, expreso e informado del titularCONSENTIMIENTO
2Cumplimiento de una obligacion legalOBLIGACION_LEGAL
3Proteccion de intereses vitales del titularINTERES_VITAL
4Interes publico o ejercicio de poderes publicosINTERES_PUBLICO
5Interes legitimo del responsable del tratamientoINTERES_LEGITIMO
6Ejecucion de un contrato con el titularEJECUCION_CONTRATO

Modulo 2 Infraestructura de Gobernanza y RBAC Arts. 17, 20

Configuracion Inicial Antes de ejecutar cualquier modulo, defina las variables abajo con su usuario y email. Estas variables se usan a lo largo de todo el entrenamiento.

Modulo 4 Tags Personalizados para Ley 81 Arts. 6, 8-9, 17

Ademas de los tags de sistema (clasificacion automatica), creamos tags personalizados para documentar metadatos exigidos por la Ley 81: base legal, finalidad, periodo de retencion, y responsables.

1 Crear Tags Ley 81

USE ROLE LEY81_DATA_STEWARD;
USE SCHEMA LEY81_GOVERNANCE.TAGS;

CREATE OR REPLACE TAG LEY81_DATA_CATEGORY
  ALLOWED_VALUES
    'DATO_PERSONAL',
    'DATO_PERSONAL_SENSIBLE',
    'DATO_ANONIMIZADO',
    'NO_PERSONAL'
  COMMENT = 'Clasificacion del dato conforme Arts. 1-5 de la Ley 81';

CREATE OR REPLACE TAG LEY81_BASE_LEGAL
  ALLOWED_VALUES
    'CONSENTIMIENTO',
    'OBLIGACION_LEGAL',
    'INTERES_VITAL',
    'INTERES_PUBLICO',
    'INTERES_LEGITIMO',
    'EJECUCION_CONTRATO'
  COMMENT = 'Base legal para tratamiento conforme Arts. 8-9 de la Ley 81';

CREATE OR REPLACE TAG LEY81_FINALIDAD
  COMMENT = 'Descripcion de la finalidad del tratamiento (Art. 6, num. 1)';

CREATE OR REPLACE TAG LEY81_RETENCION
  COMMENT = 'Periodo de retencion en dias (Art. 17, num. 5)';

CREATE OR REPLACE TAG LEY81_RESPONSABLE
  COMMENT = 'Nombre del responsable del tratamiento (Art. 5)';

CREATE OR REPLACE TAG LEY81_ENCARGADO

Herencia de Tags y Tag-Based Masking Los tags de metadatos (BASE_LEGAL, FINALIDAD, RETENCION, RESPONSABLE) se aplican a la tabla y son heredados por todas las columnas. El tag LEY81_DATA_CATEGORY se aplica individualmente por columna para evitar que columnas no-PII (como DEPARTAMENTO, CIUDAD, PROVINCIA) sean enmascaradas por el tag-based masking del Modulo 5. Las columnas sensibles (GENERO, ETNIA) reciben DATO_PERSONAL_SENSIBLE.

Modulo 5 Politicas de Enmascaramiento Dinamico Arts. 20, 6

Las masking policies protegen datos personales en tiempo de consulta. El dato original permanece intacto en la tabla, pero usuarios no autorizados ven valores enmascarados.

1 Crear Masking Policies por Tipo de Dato

Enmascaramiento de Cedula 
USE ROLE LEY81_PRIVACY_ADMIN;

CREATE OR REPLACE MASKING POLICY LEY81_GOVERNANCE.POLICIES.MASK_CEDULA
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY81_OFICIAL_DATOS') THEN val
    WHEN IS_ROLE_IN_SESSION('LEY81_PRIVACY_ADMIN') THEN val
    ELSE CONCAT(
      LEFT(val, POSITION('-' IN val)),
      '***-****'
    )
  END
  COMMENT = 'Enmascara cedula para roles no autorizados (Art. 20 Ley 81)';
Enmascaramiento de Email 
CREATE OR REPLACE MASKING POLICY LEY81_GOVERNANCE.POLICIES.MASK_EMAIL
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY81_OFICIAL_DATOS') THEN val
    WHEN IS_ROLE_IN_SESSION('LEY81_PRIVACY_ADMIN') THEN val
    ELSE REGEXP_REPLACE(val, '.+\\@', '*****@')
  END
  COMMENT = 'Enmascara parte local del email (Art. 20 Ley 81)';
Enmascaramiento de Telefono 
CREATE OR REPLACE MASKING POLICY LEY81_GOVERNANCE.POLICIES.MASK_PHONE
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY81_OFICIAL_DATOS') THEN val
    ELSE CONCAT('+507 ****-', RIGHT(val, 4))
  END
  COMMENT = 'Enmascara telefono conservando ultimos 4 digitos';
Enmascaramiento Generico (String, Number, Date) 
CREATE OR REPLACE MASKING POLICY LEY81_GOVERNANCE.POLICIES.MASK_PII_STRING
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY81_OFICIAL_DATOS') THEN val
    WHEN IS_ROLE_IN_SESSION('LEY81_PRIVACY_ADMIN') THEN val
    ELSE '***PROTEGIDO***'
  END
  COMMENT = 'Enmascaramiento generico para strings con datos personales';

CREATE OR REPLACE MASKING POLICY LEY81_GOVERNANCE.POLICIES.MASK_PII_NUMBER
  AS (val NUMBER) RETURNS NUMBER ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY81_OFICIAL_DATOS') THEN val
    ELSE NULL
  END
  COMMENT = 'Enmascaramiento generico para numeros con datos personales';

CREATE OR REPLACE MASKING POLICY LEY81_GOVERNANCE.POLICIES.MASK_PII_DATE
  AS (val DATE) RETURNS DATE ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY81_OFICIAL_DATOS') THEN val
    ELSE DATE_FROM_PARTS(1900, 01, 01)
  END
  COMMENT = 'Enmascaramiento generico para fechas con datos personales';

2 Aplicar Policies Directamente en las Columnas

ALTER TABLE EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES MODIFY COLUMN

ALTER TABLE EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES MODIFY COLUMN
  EMAIL SET MASKING POLICY LEY81_GOVERNANCE.POLICIES.MASK_EMAIL;

ALTER TABLE EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES MODIFY COLUMN
  TELEFONO SET MASKING POLICY LEY81_GOVERNANCE.POLICIES.MASK_PHONE;

ALTER TABLE EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES MODIFY COLUMN

3 Tag-Based Masking (Enfoque Escalable)

USE ROLE LEY81_PRIVACY_ADMIN;

Modulo 7 Politicas de Proyeccion (Projection Policies) Art. 6 num. 3, Art. 10, Art. 20

Las Projection Policies son la tercera capa de defensa de Snowflake. Mientras las masking policies transforman valores visibles y las Row Access Policies filtran filas, las projection policies impiden que una columna aparezca en el resultado final de un query — implementando el principio de proporcionalidad (Art. 6, numeral 3) de la Ley 81.

AspectoRow Access PolicyProjection PolicyMasking Policy
Que controlaCuales FILAS el usuario veCuales COLUMNAS aparecen en el resultadoComo los VALORES aparecen
EnforcementFiltra silenciosamenteFAIL (bloquea query) o NULLIFY (retorna NULL)Transforma el valor
Uso en WHERE/JOINN/AColumna utilizable — solo el output es bloqueadoOpera sobre valor enmascarado
Articulos Ley 81Art. 6, num. 1 (Finalidad)Art. 6, num. 3 (Proporcionalidad) / Art. 10 (Sensibles)Art. 20 (Seguridad)
Defensa en Profundidad — Orden de Evaluacion en Snowflake
Capa 1: Row Access Policy → filtra FILAS (quien ve cuales registros)
Capa 2: Projection Policy → bloquea COLUMNAS en el output (quien ve cuales campos)
Capa 3: Masking Policy → transforma VALORES visibles (como aparecen los datos)

En la tabla CLIENTES, las tres capas estan activas simultaneamente.

1 Crear Projection Policies

USE ROLE ACCOUNTADMIN;
GRANT CREATE PROJECTION POLICY ON SCHEMA LEY81_GOVERNANCE.POLICIES
  TO ROLE LEY81_PRIVACY_ADMIN;
GRANT APPLY PROJECTION POLICY ON ACCOUNT TO ROLE LEY81_PRIVACY_ADMIN;

USE ROLE LEY81_PRIVACY_ADMIN;

CREATE OR REPLACE PROJECTION POLICY LEY81_GOVERNANCE.POLICIES.PROJ_SENSITIVE_BLOCK
  AS () RETURNS PROJECTION_CONSTRAINT ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY81_OFICIAL_DATOS')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    WHEN IS_ROLE_IN_SESSION('LEY81_PRIVACY_ADMIN')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    ELSE PROJECTION_CONSTRAINT(ALLOW => false)
  END
  COMMENT = 'Bloquea proyeccion de datos sensibles (Art. 10 Ley 81)';

CREATE OR REPLACE PROJECTION POLICY LEY81_GOVERNANCE.POLICIES.PROJ_PII_NULLIFY
  AS () RETURNS PROJECTION_CONSTRAINT ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY81_OFICIAL_DATOS')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    WHEN IS_ROLE_IN_SESSION('LEY81_PRIVACY_ADMIN')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    ELSE PROJECTION_CONSTRAINT(ALLOW => false, ENFORCEMENT => 'NULLIFY')
  END
  COMMENT = 'Retorna NULL para columnas PII no autorizadas (Art. 6, num. 3 Ley 81)';

Modulo 8 Derechos del Titular (ARCO) Arts. 13-16

Los Arts. 13-16 de la Ley 81 garantizan al titular derechos sobre sus datos, conocidos como derechos ARCO (Acceso, Rectificacion, Cancelacion, Oposicion). Implementamos cada derecho como un stored procedure con auditoria automatica.

Derecho ARCOArticuloDescripcionProcedure
AccesoArt. 13Confirmar existencia y obtener acceso a los datosARCO_ACCESS
RectificacionArt. 13Corregir datos inexactos o desactualizadosARCO_CORRECTION
CancelacionArt. 13Eliminar o anonimizar datos innecesariosARCO_DELETE
PortabilidadArt. 16Exportar datos a otro proveedorARCO_PORTABILITY

1 Crear Tabla de Auditoria ARCO

USE ROLE LEY81_OFICIAL_DATOS;

CREATE OR REPLACE TABLE LEY81_GOVERNANCE.AUDIT.ARCO_LOG (
  REQUEST_ID    STRING DEFAULT UUID_STRING(),
  REQUEST_TYPE  STRING,
  TITULAR_ID    STRING    COMMENT 'Cedula o identificador del titular',
  REQUESTED_BY  STRING DEFAULT CURRENT_USER(),
  REQUESTED_AT  TIMESTAMP_LTZ DEFAULT CURRENT_TIMESTAMP(),
  STATUS        STRING DEFAULT 'PENDIENTE',
  COMPLETED_AT  TIMESTAMP_LTZ,
  DETAILS       VARIANT
)
COMMENT = 'Log de solicitudes de derechos del titular (Arts. 13-16 Ley 81)';

2 Derecho de Acceso (Art. 13)

CREATE OR REPLACE PROCEDURE LEY81_GOVERNANCE.AUDIT.ARCO_ACCESS(
  TITULAR_CEDULA STRING
)
RETURNS TABLE()
LANGUAGE SQL
AS
$$
BEGIN
  INSERT INTO LEY81_GOVERNANCE.AUDIT.ARCO_LOG
    (REQUEST_TYPE, TITULAR_ID, STATUS, COMPLETED_AT)
  VALUES
    ('ACCESO', :TITULAR_CEDULA, 'CONCLUIDO', CURRENT_TIMESTAMP());

  LET rs RESULTSET := (
    SELECT ID, NOMBRE, CEDULA, EMAIL, TELEFONO, FECHA_NACIMIENTO,
           DIRECCION, CIUDAD, PROVINCIA, CORREGIMIENTO, FECHA_REGISTRO
    FROM EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES
    WHERE CEDULA = :TITULAR_CEDULA
  );
  RETURN TABLE(rs);
END;
$$;

3 Derecho de Rectificacion (Art. 13)

CREATE OR REPLACE PROCEDURE LEY81_GOVERNANCE.AUDIT.ARCO_CORRECTION(
  TITULAR_CEDULA STRING,
  CAMPO          STRING,
  NUEVO_VALOR    STRING
)
RETURNS STRING
LANGUAGE SQL
AS
$$
BEGIN
  INSERT INTO LEY81_GOVERNANCE.AUDIT.ARCO_LOG
    (REQUEST_TYPE, TITULAR_ID, DETAILS)
  SELECT 'RECTIFICACION', :TITULAR_CEDULA,
     OBJECT_CONSTRUCT('campo', :CAMPO, 'nuevo_valor', :NUEVO_VALOR);

  IF (:CAMPO = 'EMAIL') THEN
    UPDATE EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES
    SET EMAIL = :NUEVO_VALOR WHERE CEDULA = :TITULAR_CEDULA;
  ELSEIF (:CAMPO = 'TELEFONO') THEN
    UPDATE EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES
    SET TELEFONO = :NUEVO_VALOR WHERE CEDULA = :TITULAR_CEDULA;
  ELSEIF (:CAMPO = 'DIRECCION') THEN
    UPDATE EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES
    SET DIRECCION = :NUEVO_VALOR WHERE CEDULA = :TITULAR_CEDULA;
  ELSE
    RETURN 'Error: Campo no permitido para rectificacion via ARCO.';
  END IF;

  UPDATE LEY81_GOVERNANCE.AUDIT.ARCO_LOG
  SET STATUS = 'CONCLUIDO', COMPLETED_AT = CURRENT_TIMESTAMP()
  WHERE TITULAR_ID = :TITULAR_CEDULA
    AND REQUEST_TYPE = 'RECTIFICACION'
    AND STATUS = 'PENDIENTE';

  RETURN CONCAT('Campo ', :CAMPO, ' rectificado con exito para el titular ', :TITULAR_CEDULA);
END;
$$;

4 Derecho de Cancelacion / Anonimizacion (Art. 13)

CREATE OR REPLACE PROCEDURE LEY81_GOVERNANCE.AUDIT.ARCO_DELETE(
  TITULAR_CEDULA STRING
)
RETURNS STRING
LANGUAGE SQL
AS
$$
BEGIN
  LET cnt NUMBER := (
    SELECT COUNT(*) FROM EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES
    WHERE CEDULA = :TITULAR_CEDULA
  );

  IF (:cnt = 0) THEN
    RETURN 'Error: Titular no encontrado.';
  END IF;

  UPDATE EMPRESA_DEMO_PA.DATOS_CLIENTES.CLIENTES
  SET
    NOMBRE           = 'ANONIMIZADO',
    CEDULA           = 'X-XXX-XXXX',
    EMAIL            = CONCAT('anonimizado_', ID, '@removed.ley81'),
    TELEFONO         = '+507 0000-0000',
    FECHA_NACIMIENTO = DATE_FROM_PARTS(1900, 01, 01),
    DIRECCION        = 'ELIMINADO',
    CIUDAD           = 'ELIMINADO',
    PROVINCIA        = 'XX',
    CORREGIMIENTO    = 'ELIMINADO',
    GENERO           = NULL,
    ETNIA            = NULL
  WHERE CEDULA = :TITULAR_CEDULA;

  INSERT INTO LEY81_GOVERNANCE.AUDIT.ARCO_LOG
    (REQUEST_TYPE, TITULAR_ID, STATUS, COMPLETED_AT)
  VALUES
    ('CANCELACION', :TITULAR_CEDULA, 'CONCLUIDO', CURRENT_TIMESTAMP());

1 Auditoria de Acceso a Datos Personales

USE ROLE ACCOUNTADMIN;

SELECT
  ah.USER_NAME,
  qh.ROLE_NAME,
  ah.QUERY_START_TIME,
  boa.VALUE:objectName::STRING AS OBJECT_ACCESSED,
  boa.VALUE:objectDomain::STRING AS OBJECT_TYPE,
  ah.QUERY_ID
FROM SNOWFLAKE.ACCOUNT_USAGE.ACCESS_HISTORY ah
  JOIN SNOWFLAKE.ACCOUNT_USAGE.QUERY_HISTORY qh
    ON ah.QUERY_ID = qh.QUERY_ID
  ,LATERAL FLATTEN(input => ah.BASE_OBJECTS_ACCESSED) boa
WHERE ah.QUERY_START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
  AND boa.VALUE:objectName::STRING ILIKE '%CLIENTES%'
ORDER BY ah.QUERY_START_TIME DESC
LIMIT 100;

2 Reporte de Cobertura de Tags Ley 81

SELECT
  t.TABLE_CATALOG AS DATABASE_NAME,
  t.TABLE_SCHEMA  AS SCHEMA_NAME,
  t.TABLE_NAME,
  t.ROW_COUNT,
  COALESCE(tr.TAG_VALUE, '*** SIN TAG ***') AS LEY81_CATEGORY,
  CASE
    WHEN tr.TAG_VALUE IS NOT NULL THEN 'CONFORME'
    ELSE 'PENDIENTE'
  END AS STATUS_CUMPLIMIENTO
FROM SNOWFLAKE.ACCOUNT_USAGE.TABLES t
LEFT JOIN SNOWFLAKE.ACCOUNT_USAGE.TAG_REFERENCES tr
  ON t.TABLE_CATALOG = tr.OBJECT_DATABASE
  AND t.TABLE_SCHEMA = tr.OBJECT_SCHEMA
  AND t.TABLE_NAME = tr.OBJECT_NAME
  AND tr.TAG_NAME = 'LEY81_DATA_CATEGORY'
  AND tr.DOMAIN = 'TABLE'
WHERE t.DELETED IS NULL
  AND t.TABLE_SCHEMA != 'INFORMATION_SCHEMA'
ORDER BY STATUS_CUMPLIMIENTO DESC, t.TABLE_CATALOG, t.TABLE_SCHEMA;
